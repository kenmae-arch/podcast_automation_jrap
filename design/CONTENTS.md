デザイン判断は DESIGN-BRIEF.md を参照。矛盾したときは本ファイルが優先。

## 1. 番組の基本情報

- **番組名**: 日本語ラップ アルバム全曲解説
- **キッカー/英語表記**: J-RAP DEEP DIVE
- **リード文(現行)**: 日本語ラップの名盤を、1曲ずつじっくり深掘りするポッドキャスト。制作背景・リリックのテーマ・音楽的な仕掛けを、1話1曲で解説します。
- **編成**: 1シリーズ=1アルバム、1話=1曲。1話 4,000〜6,000字(約10〜15分)の長尺。
- **配信ページ**: https://kenmae-arch.github.io/podcast_automation_jrap/
- **RSS**: https://kenmae-arch.github.io/podcast_automation_jrap/feed.xml
- **姉妹番組(海外編)**: https://kenmae-arch.github.io/podcast_automation_music/ — トンマナは意図的に変える(DESIGN-BRIEF.md §2)

## 2. 姉妹番組との仕様上の相違点(重要)

- 本番組は **音声をサイト(GitHub Pages)で自前配信しており、サイト内に `<audio>` プレーヤーがある**。
  姉妹番組サイトの「ポッドキャスト音声はサイト内で再生しない」原則(HANDOFF.md §1.1)は **本サイトには適用しない**。
  ただし将来 Spotify / Apple Podcasts 等のバッジ導線を追加する可能性はある。
- エピソードデータは `docs/episodes.json` が唯一の情報源。Web側で事実を追加しない(この原則は姉妹番組と同じ)。

## 4. エピソードタイトルの型

`{アーティスト}『{アルバム}』全曲解説 #{n} {キャッチコピー}『{曲名}』`

例:
- Mall Boyz『Mall Tape』全曲解説 #1 上昇の合図『Higher』
- ZORN『新小岩』全曲解説 #3 土手と夕焼けの詩学『Memory Lane』
- ZORN『新小岩』全曲解説 #8 マイク1本という原点『One Mic feat. KREVA』

→ 「#n + キャッチコピー + 曲名」がタイトル資産。デザインはこの日本語コピーを主役にできる。

## 5. ページ構成(想定)

現行は `docs/index.html` の1ページ構成。リニューアル後も GitHub Pages の静的サイトとし、
姉妹番組の情報設計(HOME / シリーズ一覧 / シリーズ詳細 / エピソード詳細 / ABOUT)を踏襲するが、
**まず HOME のヒーロー(ファーストビュー)から決める**。

HOME に必要な要素:
1. ヒーロー(番組名・キッカー・リード文・現在連載中シリーズへの導線)
2. 連載中シリーズの棚(『新小岩』残り2話、進捗表示)
3. 完結シリーズの棚(『Mall Tape』全4話)
4. エピソード一覧(日付・タイトル・要約・audio プレーヤー)
5. フッター(下記の権利表記・姉妹番組リンク・GitHub リンク)

## 6. 固定文言

- 権利表記(フッター必須): 「歌詞の朗読・引用は行わず、批評・解説を目的とした番組です。楽曲の権利は各権利者に帰属します。」
- 事実と解釈を混ぜない: 編集上の解釈は「このシリーズでは〜と捉えます」の形を守る(姉妹番組 CONTENTS.md §15 と同じ原則)。

## 7. データソース

- `docs/episodes.json` … title / description / published / audio_file / image(シリーズアート) / guid
- 欠損フィールドは **非表示** にする。「不明」「TBD」等の代替文字列を出さない(姉妹番組 §38 と同じ)。
